# 指标取数与计算

固定 Python 工具为 `calculate_fill`、`calculate`，注册版本 1.1.0。界面没有 PLAN 任务模式；处理阶段只展示执行进度和核验结论，不展示模型内部思考。

## 回填路径

输入为冻结 slot 计划、全部准备来源和分析合同。先重新验证意图与原文位置的语义；技术错误抛出，不能降级为业务缺口。

1. 优先查找已经有明确依据的汇总值。名称、完整上下文口径、单位、手术室、统计日期均要一致。同段多个数字必须有 slot 绑定。同日重复同值可核验，冲突不取值，不加总多个汇总版本。
2. 没有一致汇总时，仅执行 SURGERY_COUNT、EMERGENCY_COUNT、DURATION_PATIENTS 等闭合本地算子。其他口径保留 UNRESOLVED 或缺数据原因。
3. 实际/急诊按手术唯一键跨文件去重，跨日期或参与字段冲突阻止计算。已实施状态或完整实际手术时间证明事件发生；计划/取消记录不纳入，未知状态不能猜。
4. 时差人数按明确患者键逐日去重，同患者多手术不能重复算人。完整日期时间相减，严格大于原文分钟数，等于阈值不纳入。非法、负时差和仅时分不补齐。
5. 计划、首台、连台、接台、比率、平均最晚及未知来源不套用简单计数。口径、实体键、历史快照不足时写具体中文原因。

输出每项 VALUE 或 SKIP。VALUE 保留材料统计日期、单位、精确数值、来源定位、纳入/重复数量；SKIP 保留 reasonCode 与中文 reason。全部来源都有评估，不能把行数叫作台次，不能用0填缺失。

日期和文字位置当前只登记缺口，不能自动决定报告日期或猜科室。结果必须与全部 slot 一一对账；全缺口结果是诊断输出，不代表实际指标计算成功。

## 旧规则路径

`calculate` 保留既有 engine.SCHEMA 和受控算子。只执行合法 CLEAR 规则，不执行自然语言、任意 Python/SQL 或宏。分母为零、缺失与非法值按显式规则处理，不默认输出0%。旧合同不能通过新路径静默重算。

同一冻结合同、数据和运行版本应得到同一结果；报告 Skill 只能消费结果，不能再用 LLM 改写数值。
