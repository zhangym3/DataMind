# 技能管理设计：导入、导出、编辑与运行接入

日期：2026-10-30。状态：待实现的产品与技术设计；本文件不表示功能已交付。本轮不修改应用运行代码、用户数据或模型连接。

## 1. 目标与当前边界

提供独立的“技能管理”页面，让用户查看技能、导入技能包、编辑指令和资源、试运行、发布启用、导出及回滚。发布后的内容必须被相应阶段实际使用；每次处理固定所用版本，后续编辑不能改变已经开始的处理。

与[新的 LangGraph 方案](langgraph-redesign-2026-10-30.md)保持一致：用户问题和数据决定分析目标，指标只作为辅助口径解释；技能提供解析、规划、计算和输出能力，不能把“匹配到指标”重新变成普通查询的前置条件。

当前工程已经具备的基础：

| 现状 | 对本设计的影响 |
| --- | --- |
| `insight_agent/skills.py` 固定注册四个 ID，并由 `invoke()` 分派 Python 工具 | 导入包不能仅凭声明获得新的 Python 工具或算子 |
| `skills/` 包含 `SKILL.md`、参考资料及 `agents/openai.yaml`，目前不动态加载这些文件执行 | 必须增加内容加载、阶段绑定和指令合成，不能只做文件编辑器 |
| 提取指令、输出结构及运行版本的哈希已经进入 `runtime_manifest()` | 技能升级要接入冻结合同和恢复校验，不能用新指令恢复旧批次 |
| `AppService.dispatch`、SQLite 对象、blob、事件及桌面文件选择器可复用 | 无需另建 Web 服务，新增 `skill.*` 业务接口和原生文件桥接 |
| PyInstaller 当前未打包仓库 `skills/` | 实现时必须把内置技能资源加入打包清单，源码和 EXE 使用同一份版本内容 |

技能与资料分开管理。聊天中的 Word、Excel、指标说明不会自动安装为技能；技能包在“技能管理”中导入。

## 2. 页面与操作设计

### 2.1 入口与列表

左侧工作空间增加“技能管理”，与“数据对话”“指标管理”并列。进入时展示全部技能；右侧数据上下文隐藏，保留主界面的字号与缩放设置。

顶部操作为“导入技能”“新建技能”“批量导出”。支持按名称、说明、技术 ID 搜索，以及按内置/自定义、适用阶段、启用状态、兼容状态筛选。

| 列 | 展示内容 |
| --- | --- |
| 选择 | 多选，仅用于批量导出 |
| 技能 | 中文名称、简短描述、技术 ID |
| 来源 | 内置、本地导入、本地创建；导入者自报的作者不作为可信凭据 |
| 适用阶段 | 文档解析、数据接入、语义规划、确定性计算、结果组织等中文标签 |
| 版本 | 当前启用版本；另标记“有未发布修改” |
| 状态 | 已启用、未启用或已归档；单独显示“缺少适配器”“不兼容”等原因 |
| 操作 | 查看、编辑/派生、版本、导出、更多 |

技能数量不与指标数量混淆。导入成功、结构校验通过、试运行通过和已启用分别展示。

### 2.2 详情与编辑器

详情采用宽编辑页，顶部显示名称、版本、草稿状态及“保存草稿 / 校验 / 试运行 / 发布 / 导出”。左侧为文件树，中央为编辑和预览，右侧为本文件的影响范围及校验问题。

| 页签 | 内容 |
| --- | --- |
| 基本信息 | 名称、描述、标签、作者、版本说明及兼容要求；技术 ID 创建后固定 |
| 指令与文件 | `SKILL.md`、阶段指令、参考资料、模板、示例；Markdown 原文/预览切换 |
| 运行绑定 | 选择应用已支持的能力与阶段，查看输入输出合同、参数和数据范围 |
| 校验与试运行 | 错误定位、样例输入、实际阶段、结构结果、耗时、来源定位及差异 |
| 版本记录 | 发布说明、修改人/时间、文件差异、当前启用标记及回滚入口 |

编辑器必须明确标注文件用途：“仅说明”“用于模型指令”“运行参数”“报告模板”“脚本资源，需适配器接入”。默认打开所选阶段实际使用的指令文件，避免用户修改说明却误以为行为已变化。

- 支持文本文件新增、重命名、删除，以及资源文件导入；重命名或删除被引用文件时，同时提示并校验引用。
- Markdown 支持预览，JSON/YAML 支持语法错误定位；Markdown 中的 HTML 不执行，预览不加载外部脚本或图片。
- Python 文件可以查看、编辑、保存和导出；编辑结果不会自动替换应用中的 Python 模块，执行规则见第 6 节。
- `Ctrl+S` 保存草稿，`Ctrl+F` 查找；离开存在未保存修改的页面时提供“保存后离开 / 放弃修改 / 留在此页”。
- 可将草稿另存为本地恢复副本；草稿自动暂存不等于发布，不自动影响分析。
- 内置版本只读；点击“编辑”时创建自定义派生技能，保留原技能和派生关系。已发布自定义版本也通过新草稿修改。

### 2.3 导入流程

```mermaid
flowchart LR
    A[选择 ZIP、文件夹或 SKILL.md] --> B[检查文件并读取清单]
    B --> C[识别能力与兼容性]
    C --> D[预览内容、差异与冲突]
    D --> E[导入为草稿]
    E --> F[编辑、校验与试运行]
    F --> G[发布版本]
    G --> H[启用或设为阶段默认]
    G --> I[导出技能包]
```

1. 支持 `.zip` 标准包、已有技能文件夹、单个 `SKILL.md`；文件选择、拖放及 `Ctrl+V` 文件粘贴进入同一链路，仅在技能页面触发技能导入。
2. 解包后先展示名称、版本、文件数、适用能力、兼容结果及与本地版本的差异。此时尚未改变启用配置。
3. 没有 DataMind 清单的通用技能，读取 `SKILL.md` 的 `name`、`description` 等元数据，提示选择支持的能力和阶段；未绑定时可先存为草稿。
4. 有 `scripts/` 或未知扩展能力时如实列出；导入文件成功不代表脚本已经获得执行入口。`agents/openai.yaml` 可保留并查看，不作为模型 Key、模型连接或工具授权来源。
5. 用户确认内容及冲突处理后导入。默认保存草稿；兼容且通过发布检查后可执行“发布并启用”，无需额外导入任务页面。
6. 展示逐包结果：成功、复用已有内容、取消或失败；失败显示具体文件和原因，已启用版本保持有效。

导入保留只读原包及 `sourcePackageHash`，另建本地草稿；本地草稿状态不反向修改原包。来源声明的“已发布”不等于本机校验通过或启用。未修改的来源发布包通过检查后可按原版本登记发布；修改内容后按版本冲突规则处理。

冲突规则：

| 情况 | 处理 |
| --- | --- |
| 同 ID、同版本、同内容哈希 | 幂等复用已有版本，不重复建记录、不自动启用 |
| 同 ID、同版本、不同内容 | 不覆盖；提供“作为新版本草稿”“派生为新技能”或“跳过” |
| 同 ID、较新/较旧版本 | 可保存历史版本；启用动作独立，不因版本号更大就自动替换 |
| 同中文名称、不同 ID | 允许并存；列表展示 ID 和来源，绑定时明确选择 |
| 与内置 ID 冲突 | 相同内容复用；不同内容建立自定义派生，不写安装目录 |
| 包含多个技能 | 逐项勾选及处理冲突；每个技能原子提交，逐包报告成功与失败 |

### 2.4 进度与取消

导入面板展示真实阶段：“检查文件 → 读取元数据 → 复制资源/校验哈希 → 检查兼容性 → 等待确认 → 保存 → 完成”。显示已处理文件数/总数、字节数、当前文件和单调时钟计算的耗时；只有可计量阶段显示百分比。

预检和文件处理放在本地后台操作中，不阻塞 Qt 主线程；进度通过事件增量刷新，界面不增加“任务模式”。取消只清理本次暂存，不能删除已有技能。确认提交已完成后显示“已导入”，不能再表示为已取消。

### 2.5 导出流程

- 单项导出可选择某个已发布版本、当前草稿或导入时保留的原包；批量导出按勾选技能及明确的版本列表生成集合 ZIP，默认各技能当前启用版本，不默认导出全部历史。没有启用版本时，逐项确认导出草稿或某个已发布版本。
- 默认导出完整资源：清单、指令、被引用参考、模板、脚本、依赖说明和可共享样例。提供“仅导出 SKILL.md”快捷项，并标注其不包含完整运行资源。
- 草稿包标记为草稿，导入后仍为草稿。已发布包保留原版本和内容哈希；在另一台设备导入也不自动启用。
- 导出内容预览列出全部文件。自动生成的包不包含 API Key、模型连接密钥、业务数据库、真实处理缓存、运行日志或本机绝对路径；文本中发现疑似凭据或业务样例时定位给用户，修改后再导出。检测不能保证识别所有隐私内容。
- 先在应用导出目录生成完整临时包，校验成功后通过原生“另存为”保存；不覆盖原技能。取消另存为不改变技能状态。
- 同一快照、相同清单内容的导入→导出→再导入保持内容哈希一致；ZIP 时间戳、压缩方式、安装时间和本机启用状态不参与内容哈希。导出原包保留原哈希；把来源发布包转换为草稿包时，`artifactState` 改为 `DRAFT`，重新计算哈希并保留来源哈希，不宣称仍是原发布包。

## 3. 包格式与兼容规则

标准包为 UTF-8 文本及原始二进制资源，允许单层包装目录：

```text
skill-package/
  skill.json
  SKILL.md
  checksums.json
  instructions/catalog.md
  references/terms.md
  templates/
  scripts/
  tests/catalog-case.json
```

`SKILL.md` 保留通用技能格式；`skill.json` 描述 DataMind 如何接入。示例中的扩展字段为拟定合同：

```json
{
  "schemaVersion": "datamind.skill-package/1.0",
  "id": "local.word-spec-policy",
  "name": "指标说明解析（本院）",
  "description": "补充术语解释，保留文档证据和待确认项",
  "version": "1.0.0",
  "artifactState": "PUBLISHED",
  "kind": "CONFIGURABLE_ADAPTER",
  "entry": "SKILL.md",
  "requires": {
    "app": ">=1.0.0 <2.0.0",
    "capabilityApi": "1"
  },
  "bindings": [
    {
      "capability": "surgery-word-spec.catalog",
      "stage": "metric_catalog",
      "instructionFile": "instructions/catalog.md",
      "referenceFiles": ["references/terms.md"],
      "parameters": {}
    }
  ],
  "tests": ["tests/catalog-case.json"]
}
```

通用 `SKILL.md` 可直接被绑定为某个受支持阶段的 `instructionFile`；普通说明文件不会被偷偷拼进每次模型请求。注册能力的输入/输出 Schema 和允许参数由应用提供，包只能引用，不能自行放宽合同。

`kind` 首版支持 `CONFIGURABLE_ADAPTER`（绑定应用能力）和 `RESOURCE_ONLY`（资料型技能）。后者可完成编辑、静态校验、版本发布与导出，但没有执行绑定，界面显示“资料型，未接入执行”，不提供启用。要参与运行，须创建绑定受支持能力的新草稿并重新发布。

`checksums.json` 保存除自身以外的所有包文件的相对路径、大小和 SHA-256，包含 `skill.json`；`packageHash` 为规范化、按路径排序的该文件清单的哈希，避免哈希自引用。哈希用于完整性和去重，不代表作者可信或代码可执行。

集合包使用 `bundle.json` 列出 `skills/<id>/<version>/` 及每个包哈希。首版只支持应用能力/API 依赖和包内资源引用，不引入技能间任意依赖或自动下载；缺少 Python 库/适配器时标明能力不可用，不在导入时运行安装命令。

预检需要覆盖以下实际文件问题：

- 拒绝绝对路径、`..` 越界、Windows 盘符/UNC、备用数据流、设备保留名、符号链接和路径重解析；目的路径解析后必须仍在本次暂存目录内。
- Windows 大小写不敏感规则下检测重名、末尾空格/点及文件/目录冲突，避免解包时相互覆盖。
- ZIP 同时检查压缩前后大小、总文件数和解压过程的实际计数；不递归展开嵌套 ZIP。
- 建议初始上限：单包压缩 20 MiB、解压 100 MiB、500 文件、单文本 2 MiB、单二进制 50 MiB、8 层目录；集合包另设总上限并逐包执行这些限制，超限给出位置和原因。
- UTF-8 解码失败时保留原件并提示选择编码后生成新草稿，不静默替换乱码。二进制文件不进入文本编辑器。
- 核验必需文件、清单版本、每个引用文件和校验和；发现未知运行字段时定位错误，不忽略后假装已生效。

## 4. 草稿、发布、启用与回滚

内容状态和使用状态分别管理：

| 对象 | 状态或字段 | 规则 |
| --- | --- | --- |
| 技能系列 | `enabled`、`archivedAt`、`activeReleaseId` | 决定新处理是否可选，不包含可变发布内容 |
| 工作草稿 | `DRAFT`、`revision` | 可多次保存；用 revision 防止同时编辑覆盖 |
| 发布版本 | `PUBLISHED`、语义版本、`packageHash` | 不可变；保存后重新编辑必须创建草稿 |
| 校验记录 | `contentHash`、结果、适配器版本、检查时间 | 绑定具体内容；编辑使旧结果失效 |
| 兼容结果 | `COMPATIBLE / UNBOUND / INCOMPATIBLE` | 根据当前应用能力计算，与是否已发布分开 |

“保存草稿”只持久化编辑。“发布”在同一事务中核验草稿 revision、内容哈希、兼容性、引用和校验报告，创建不可变版本；不要求为了修改说明先调用在线模型。资料型技能按静态合同发布，保持 `UNBOUND`；能力型技能必须通过绑定及运行合同检查，不能把未接入能力标为已就绪。

行为变更需通过对应适配器自带的本地合同检查和必要回归样例；包自带样例可补充检查，不能通过编辑样例取消应用必需检查。在线试运行是独立动作，未执行时明确标注“未进行在线试运行”，不伪造通过。

发布可选择“仅发布”或“发布并启用”。版本号与草稿 revision 分开：自动建议下一个版本，但不在每次保存时增加发布版本。同一 ID 和版本只允许一个内容哈希。

启用后可设为指定阶段默认；同一互斥阶段和作用域只能有一个默认技能版本。用户也可以仅在某个对话显式指定版本，普通聊天无需每次手动选技能。

回滚是将默认绑定指向仍兼容的历史发布版本，记录原因和操作者；历史版本、旧结果及其合同都不改写。停用影响之后的新处理，已固定版本的运行按原合同完成；因缺失文件或适配器确实无法恢复时精确报错，不换新版本续跑。

自定义技能可归档，引用中的发布版本及资源保留。内置技能不提供物理删除；已被运行、解析产物、草稿基线或历史合同引用的内容不参与文件清理。

## 5. 试运行与反馈

试运行支持当前未保存编辑内容，先创建临时内容快照；不必发布、启用或创建数据对话。结果绑定此快照哈希，不回写正式指标库、资料和分析结果。

| 类型 | 输入及输出 | 边界 |
| --- | --- | --- |
| 静态校验 | 语法、元数据、引用、阶段绑定、Schema、参数、模板占位符 | 即时本地检查，不调用模型 |
| 本地能力试运行 | 内置合成样例或用户选择的资料副本；显示结构和证据检查 | 原件只读，产物进入独立临时目录 |
| 在线指令试运行 | 选择当前已保存的模型连接，发送该阶段允许的脱敏 DTO | 立即启动独立请求，显示真实进度，不进入分析任务队列；Key 仍由原有凭据服务读取 |

长耗时检查通过异步操作回传进度并可取消，避免阻塞界面。展示耗时、输入范围、实际技能版本/哈希、所用模型连接、实际用量与额度、结构校验结果及错误定位；不展示模型内部思考，也不把“JSON 返回成功”称为业务数值验证成功。

修改文本、参数、引用或适配器后，旧试运行结果仍可查看，但标为“对应旧内容”；取消、超时、模型鉴权失败和业务缺口分别展示。

## 6. 运行能力与编辑生效方式

首版提供两种内容用途：可绑定现有受信适配器的技能，以及暂未绑定的技能资料。工具和算子仍由应用注册；新 Python 能力通过适配器开发、测试和应用交付接入。

导入或修改 `scripts/*.py` 只完成资源管理，不能直接取得主进程、数据库、凭据或任意路径访问权。若要让某脚本可运行，必须有支持该脚本协议的已注册适配器，声明允许入口、输入输出及精确代码哈希；适配器校验不匹配时显示“脚本版本未接入”。一般 Python 子进程不是操作系统安全沙箱，不能用 `subprocess` 代替此边界。

这保留当前明确的“受信 Python、资料不是命令”规则，同时支持脚本随技能包完整导入、编辑和导出。通用技能声明的任意命令不会被转换成自动执行操作。

对已有四个技能，编辑生效范围如下：

| 技能 | 可以配置并实际生效的内容 | 继续由应用控制 |
| --- | --- | --- |
| `surgery-word-spec` | 目录、提取、回填规划阶段的业务补充指令和显式参考资料 | DOC/DOCX 解析算法、证据核验、输出结构和技术错误处理 |
| `surgery-excel-ingest` | 已注册参数范围内的别名/读取选项，以及确实经过模型的字段解释阶段指令 | 表头解析、文件角色校验、原件哈希和明细出站限制；参数需逐项建立正式合同 |
| `surgery-metric-calc` | 已注册计算能力的说明、可选参数与展示文字 | 最终计算逻辑、算子实现和数值核验；指标公式属于查询合同，不借技能文本全局覆盖 |
| `surgery-word-report` | 允许编辑的报告样式、章节模板和结果说明模板 | 数值绑定、Word 原文回填位置、内容一致性；用户要求原文格式时不允许模板重排原文 |

没有相应配置合同的字段先显示只读/尚不支持，不能保存为“有效参数”。例如在 Markdown 写“按每日最早一例认定首台”，不会让当前不支持的首台算子自动实现。

指令由应用的固定规则、所选技能阶段指令和阶段数据合同合成。技能不能放宽脱敏、出站、输出结构、预算、数值来源及工具权限；用户材料始终作为资料传入。用户明确的本次分析要求进入查询计划，不被技能中的默认建议静默覆盖。

只加载节点声明的指令与参考，不把整个文件夹放入模型上下文。参考文件有文件哈希、节选定位和上下文额度；必需内容超额时给出具体诊断，不静默截断后继续声称使用完整规则。

## 7. 与 LangGraph 的绑定和恢复

技能是节点使用的版本化能力与指令，节点本身不由导入包随意创建。现有固定图先接入版本加载，之后可按新方案扩展节点。

| 场景/节点 | 选择方式 | 版本固定时机 |
| --- | --- | --- |
| 上传后的文件识别与解析 | 按文件类型和本地注册能力选择 | 导入处理首次取得执行权、读取内容之前 |
| Word 目录、定义提取或回填计划 | 选择已启用的文档技能及阶段 | 新解析代次第一批请求之前 |
| `understand_request`、`interpret_semantics`、`build_query_plan` | 使用已支持的请求理解/规划能力；未实现的阶段不能仅靠技能包激活 | 本轮首次解释和规划之前，形成 `turnSkillLock` |
| `retrieve_metric_context` | 固定检索适配器；技能可补充解释规则 | 本轮规划版本锁内；指标引用仍为可选，不阻断普通查询 |
| `prepare_data`、`compute_steps` | 按已验证计划选择注册适配器 | 计算合同固定时继承本轮已经使用的版本 |
| `compose_answer`、Word 回填及导出 | 按回答模式和用户要求选择；原文回填继续优先 | 本轮固定输出策略；之后单独导出也使用原运行记录的版本 |

选择顺序为“对话显式指定的兼容发布版本 → 工作区对应阶段默认版本 → 原有内置默认”。显式指定或已有默认绑定失效时报告精确原因，不能悄悄降级为另一套行为；只有没有用户绑定时才使用内置默认。可选增强未启用不影响基础路径，缺少必需解析/计算能力时在执行前明确提示。

`turnSkillLock` / 解析代次锁至少包含：`skillId`、`releaseId`、`packageHash`、阶段、能力/API 版本、适配器实现哈希、参数哈希、有效指令哈希和所引用资源哈希。开始解析/理解时就固定，不能等计算阶段才记录。LLM 连接版本、实际提示和请求额度仍按原网关合同冻结。

主图检查点只保存锁记录 ID/哈希。计算 Run 继承本轮实际使用的锁；批次缓存、幂等键和中间产物同时包含对应阶段的锁哈希。恢复时读取原发布内容和资源，而不是当前默认版本。

当前 `runtime_manifest()` 将全局技能注册表纳入比较。实现时拆分为固定的应用/图/算子环境与本次选中技能锁，避免“安装一个无关技能”使已有运行全部出现 `VERSION_MISMATCH`。旧合同继续由旧执行入口校验，不能直接修改历史 manifest 以跳过检查。

对话可显示“正在使用：指标说明解析（本院）v1.2.0 · 目录整理”，详细记录版本、阶段、完成项和真实错误。技能详情提供被哪些阶段、解析及运行引用的记录。

## 8. 存储、事务与事件

内置包从只读应用资源加载；自定义包和草稿属于当前数据工作区，不写 `C:/Program Files` 或仓库目录。发布文件使用现有内容寻址 blob，元数据保存在 SQLite；临时解包和未保存试运行放在工作区 `tmp/`。

| 记录 | 主要字段 |
| --- | --- |
| `skill` | ID、显示信息、来源、派生 ID、启用/归档状态、当前启用 release、revision |
| `skill_draft` | skillId、基线 release、来源原包/blob 及 sourcePackageHash、文件树/blob 引用、清单、contentHash、revision |
| `skill_release` | skillId、version、manifest、文件哈希清单、packageHash、发布说明；不可变 |
| `skill_binding` | 工作区/对话、阶段、能力、releaseId、参数及 revision |
| `skill_check` | 内容/环境哈希、检查类型、结果、诊断和必要的试运行回执 |
| `skill_lock` | 某个 turn、解析代次或 Run 的不可变选中版本和实际指令摘要 |
| `skill_operation` | 导入/导出/试运行操作 ID、阶段、计数、取消标记、终态及暂存引用 |

所有写入接口带 `requestId`，编辑和切换同时带 `expectedRevision`。重复提交返回同一结果；冲突返回当前 revision，提示比较后重试，不覆盖另一处修改。

先写入并校验不可变 blob，再在 SQLite 短事务中提交元数据及事件；失败的暂存或无引用 blob 延迟清理。批量导入按技能原子提交，不把部分文件登记成完整版本。发布和默认绑定切换在同一事务里检查状态。

事件使用 `skill:<id>` / `skill-operation:<id>` 作用域，包含 `operationId`、顺序号、阶段、完成/总计、时间和诊断码。恢复页面按顺序号补读，避免重排或重复显示进度。

工作区备份、恢复、迁移和引用校验必须增加上述对象及其 blob；恢复后重新计算与当前应用的兼容性。历史引用存在时不能清理资源。应用升级新增内置版本，保留被使用的旧内容，也不覆盖用户派生技能或默认绑定。

## 9. 业务接口

沿用 `AppService.dispatch` 与 QWebChannel，不新增对外 HTTP 服务。接口为设计名称，尚未实现：

| 接口 | 用途及关键输入 |
| --- | --- |
| `skill.list` / `skill.detail` | 搜索、分页、筛选；详情含文件树、版本及影响范围，不一次返回整个包 |
| `skill.create` / `skill.fork` | 从模板新建或由已有发布版本派生 |
| `skill.draft.get` / `skill.file.read` | 按草稿/发布 ID 和包内相对路径分段读取文本或资源元数据 |
| `skill.draft.save` | 保存当前文件变更及清单；带 expectedRevision、基线及文件哈希 |
| `skill.file.create` / `rename` / `remove` | 包内资源操作，检查路径、引用和草稿 revision |
| `skill.validate` | 校验指定草稿快照或当前编辑快照，返回文件、行列和错误码 |
| `skill.test.start` / `skill.test.cancel` | 即时独立试运行；指定快照、阶段、样例及模型连接 ID |
| `skill.release.publish` | 校验同一快照后发布；可原子激活并设置对应默认绑定 |
| `skill.release.list` / `skill.release.diff` | 版本列表及文件/指令/参数差异 |
| `skill.activate` / `skill.rollback` | 切换兼容发布版本；带 expectedRevision，不改写内容 |
| `skill.disable` / `skill.archive` | 停用新使用或归档，保留引用及历史 |
| `skill.binding.get` / `skill.binding.set` | 查看或设置工作区/对话的阶段默认；校验范围和兼容性 |
| `skill.references` | 查询运行、解析、绑定及派生引用 |
| `skill.import.prepare` | 根据原生文件桥接令牌创建预检操作，返回候选及逐包诊断 |
| `skill.import.commit` / `skill.import.cancel` | 提交冲突选择及暂存内容哈希，或取消暂存 |
| `skill.export.prepare` / `skill.export.save` | 生成指定版本/草稿集合，再通过原生另存为保存 |
| `skill.operation.detail` / `skill.operation.events` | 查询终态及按序号增量读取进度；重开页面可恢复显示 |

文件选择/目录选择通过桌面桥接返回操作令牌，浏览器不直接提交任意本机路径。试运行资料选择同样返回限定引用；正式资料原件不可被技能编辑接口修改。大文件用资源导入令牌或分段接口，不能突破现有 3 MiB 桥接请求限制。

统一错误结构沿用 `code/message/details`，`details` 增加 `operationId`、技能、文件相对路径、行列、当前 revision 和可用动作；不把内部完整路径和凭据写入普通提示。

建议错误码覆盖：`SKILL_PACKAGE_INVALID`、`SKILL_PATH_INVALID`、`SKILL_HASH_MISMATCH`、`SKILL_VERSION_CONFLICT`、`SKILL_REVISION_CONFLICT`、`SKILL_CAPABILITY_UNAVAILABLE`、`SKILL_BINDING_INCOMPATIBLE`、`SKILL_VALIDATION_FAILED`、`SKILL_RESOURCE_MISSING`、`SKILL_CONTENT_LIMIT`；模型、预算和转换器错误继续保留原始准确代码。

## 10. 实施顺序与验收

1. **运行基础**：拆分固定能力注册与技能内容，给四个内置技能生成与当前行为一致的发布快照，接入版本锁和打包资源。先保证解析、计算、回填及旧合同回归。
2. **管理闭环**：完成技能列表、文本/资源编辑、草稿、校验、发布、绑定、版本比较、回滚和引用保护。确保发布内容实际进入所绑定阶段。
3. **交换与试运行**：完成 ZIP/文件夹/单文件导入、冲突处理、完整包及批量导出、即时试运行和取消，覆盖真实进度与恢复。
4. **交付验收**：补齐工作区备份恢复、EXE 资源和不同缩放下的界面检查；通过下表后才能称为技能管理功能完成。

| 验收场景 | 通过条件 |
| --- | --- |
| 四个原有技能 | 默认行为不变，源码与打包版均能读取实际指令和资源 |
| 通用文件夹/ZIP/SKILL.md 导入 | 识别正确，可预览/绑定；未知能力明确显示未接入，不执行声明命令 |
| 同包重复导入及同版本冲突 | 重复幂等，冲突不覆盖，派生/新版本选择有效 |
| 包内异常路径、重名、超限及损坏资源 | 预检/流式解包拒绝并定位；不写出暂存目录，不留下可用的半包 |
| 编辑与保存冲突 | 未发布不影响分析，未保存可恢复/放弃；并发保存不丢失修改 |
| 编辑已绑定指令并发布 | 下一次对应阶段读取新指令及哈希，单纯改说明不冒充行为变化 |
| 编辑脚本或请求新算子 | 文件可管理，但无适配器/代码哈希不匹配时不能执行 |
| 当前草稿即时试运行 | 无需保存发布，结果对应临时哈希；不生成正式分析或改写指标 |
| 发布、设为默认、停用和回滚 | 同一阶段默认唯一，显式绑定不被隐式替换，旧内容可追溯 |
| 长解析期间编辑、导入无关技能、切换默认 | 原批次使用原版本锁并可恢复，无关改动不使其全局版本失配 |
| 缺失旧内容或运行适配器 | 保留历史并报告准确环境缺失，不用当前版本冒充原版重算 |
| 资料型技能管理 | 可保存、校验、发布、导出；明确未接入执行，不提供无效启用 |
| 导出完整包/草稿/多技能 | 必需文件完整，草稿身份保留，取消不变更数据；同快照往返哈希一致，改变草稿/发布身份重新计算哈希 |
| 中断、取消、崩溃及重开页面 | 根据持久操作恢复状态，原子提交，不重复版本或伪造完成进度 |
| 模型连接及数据范围 | 仍用现有网关和阶段 DTO；技能包不携带 Key、不扩大出站数据 |
| Word 回填和普通语义查询 | 保留原文要求，数值来自确定性计算；没有指标参考仍可按新查询方案规划 |
| 备份、恢复、迁移、应用升级及资源清理 | 自定义内容和引用完整，恢复重新校验兼容，旧资源不被误删 |
| 125%/150% 缩放及窄窗口 | 文件树、编辑、进度、试运行和发布按钮可达，表格在自身范围滚动 |

首个完整交付以“现有受信能力的版本化配置、编辑和交换”作为范围；任意第三方 Python 插件的自动执行属于另外的运行时扩展，不能与技能文件导入混为已经实现的能力。
